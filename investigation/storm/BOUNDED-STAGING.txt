OpenUSD 25.11 bounded staging for Windows Release builds

Production behavior

Storm staging capacity is capped at 64 MiB by default, rather than sizing a
temporary allocation to the scene's entire pending upload data. When a batch
fills, queued staging copies are flushed and submitted with completion before
the CPU bytes or UMA staging slot are reused. This protects queued CPU pointers
and GPU copy source lifetimes. The existing direct path for large individual
sources is retained, but individual direct calls are also bounded to the limit.
Underestimated staging sizes grow only within the bound, instead of losing data.

HDST_MAX_STAGING_BUFFER_SIZE optionally configures the byte limit (1..1 GiB).
The default is 67108864. Invalid values warn and fall back to 64 MiB. No setting
is necessary to enable the fix. The staged path remains active.

All previous experimental per-prim tracing, staging bypass, chunk-upload switch,
and the unsuccessful upstream GL_DYNAMIC_COPY backport were removed from the
production source/build. Historical diagnostic DLLs remain in the investigation
backups. Old STORM_TRACE_* variables have no effect in the production build.

The overlay is idempotent and validates normalized source hashes. It refuses
unknown local changes or a different USD source revision. It was checked
against the pristine files inside OpenUSD-25.11.zip, applied twice successfully,
and verified to reject an unrelated local edit without overwriting it.
Thus CLEAN builds from the archive retain the fix. A new USD version requires
review/rebasing the patch and updating the hashes, not blindly reusing the overlay.

Verification

Native GPU readback tests passed at 4 KiB and the default 64 MiB; invalid zero
budget safely fell back to 64 MiB and passed. Tests run on the installed Release
DLLs. The standalone harness uses matching MaterialX compile definitions to
match the USD class layout. The first harness attempt lacked that definition
and failed; it was corrected before the tests above.

The native test is registered in USD's test configuration for future test-enabled
builds. The current dependency build has PXR_BUILD_TESTS=FALSE, so the same
regression source was built separately and run directly. The broad USD/Stageviz
test suites, Debug build, UMA, Metal and Vulkan have not been qualified here.
Batch rollover deliberately waits for completion; performance has not been
benchmarked. This favors safe buffer reuse for the local fix.

run08-bounded / subsequent run folders. Original TEMP_asm.usd is never saved.
